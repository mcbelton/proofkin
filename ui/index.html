                          Add a monitor

                          This agent runs a check of one of its folders again and again while it runs, measures availability against your objective, and opens an incident when the check keeps failing. Troubleshooting guides in Knowledge (or the debugging agent) then try to fix it.

                          Monitors run a folder's check, and none of this agent's folders has one yet. Add one in a terminal, e.g. proofkin share add app PATH --check health=COMMAND, then come back.

                          New squad

                          A squad is a group of peers. In a plan, #name runs a step on its least busy online member that can do it: one that runs the step's provider in a folder it shares with you or, for a team step, one whose folder has a team plan. Sign-offs (approve) go to a person instead: @name.

                              Sign in to Work IQ

                              Through Microsoft's Work IQ CLI on this machine (install it with npm install -g @microsoft/workiq). The CLI signs in by itself, with its own app, which your organization's admin must have approved, so Proofkin keeps no token. Signing in checks the account with Work IQ right away.

                              Your organization's own app (the hosted connection) signs in from a terminal instead, with its tenant and app id:

                              proofkin auth login workiq --profile <name> --tenant <id-or-domain> --client-id <app-id> --device-code

                              Work IQ budget

                              A Work IQ call over either budget isn't sent: it fails, saying which budget is used up, and the audit file records it as refused.

                              Import from Microsoft 365

                              Searches your Microsoft 365 with this agent's Work IQ and keeps what it finds as a knowledge topic, which plan steps use with context=. The topic keeps where it came from: Microsoft 365, with the sensitivity labels of what it kept. So it goes only to peers whose Microsoft 365 grant covers those labels.

                              Link a GitHub repository

                              It is cloned with your GitHub account and shared with the peers you pick. Each editing task runs on its own branch (p2p/…), and you open pull requests from them here.

                              Share with

                              Track plan runs on GitHub

                              Each plan run gets an issue in this repository and each step a sub-issue, assigned to your GitHub account. On the project's board their status follows the run, and pull requests from the steps' branches close them.

                              Use a private repository for task plans, such as a brief from Microsoft 365. Without one, task plans use the main repository unless tracking is off.

                              The board needs the project scope on your GitHub account's token. Without it, the runs are tracked as issues only, and the Tracker card offers to grant it.
